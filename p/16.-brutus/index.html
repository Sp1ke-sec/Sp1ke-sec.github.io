Brutus

About: In this very easy Sherlock, you will familiarize yourself with Unix auth.log and wtmp logs. We’ll explore a scenario where a Confluence server was brute-forced via its SSH service. After gaining access to the server, the attacker performed additional activities, which we can track using auth.log. Although auth.log is primarily used for brute-force analysis, we will delve into the full potential of this artifact in our investigation, including aspects of privilege escalation, persistence, and even some visibility into command execution.

介绍：在这个非常简单的夏洛克教程中，你将熟悉 Unix 的 auth.log 和 wtmp 日志。我们将探讨一个通过 SSH 服务对 Confluence 服务器进行暴力破解的场景。攻击者获得服务器访问权限后，执行了其他活动，我们可以使用 auth.log 跟踪这些活动。尽管 auth.log 主要用于暴力破解分析，但在我们的调查中，我们将深入挖掘此工件的全部潜力，包括权限提升、持久性，甚至命令执行的一些可见性。

Task 1

Analyze the auth.log. What is the IP address used by the attacker to carry out a brute force attack?

分析auth.log文件。攻击者用于实施暴力破解攻击的IP地址是什么？

auth.log 是 Debian/Ubuntu 系的认证审计日志文件。路径一般是 /var/log/auth.log。

用于记录 SSH登录、su 切换用户、sudo 执行、登录成功、登录失败、账号认证、密码校验、会话开启关闭这些登录/认证相关的活动。

1
2
3
4

┌──(root㉿kali)-[~/HTB/Brutus]
└─# cat auth.log 
Mar  6 06:18:01 ip-172-31-35-28 CRON[1119]: pam_unix(cron:session): session opened for user confluence(uid=998) by (uid=0)
......

我们先拆解一行/一条日志：

  • Mar 6 06:18:01 时间
  • ip-172-31-35-28 当前主机名
  • CRON[1119]: 进程名cron，PID是1119
  • pam_unix(cron:session): 使用 pam_unix 认证模块，场景是 cron 的会话
  • session opened for user confluence(uid=998) by (uid=0) 会话打开（登录/启动会话成功）；操作的是 uid=998 的用户，发起者是 root（uid=0）。

其它条目也差不多是这样的结构。

往下翻，发现大量的 SSH 连接请求，且大量登录失败，可知攻击者 IP 为：65.2.161.68

答案：65.2.161.68

暴力破解尝试成功，攻击者获得了服务器上一个账户的访问权限。该账户的用户名是什么？

Task 3

Identify the UTC timestamp when the attacker logged in manually to the server and established a terminal session to carry out their objectives. The login time will be different than the authentication time, and can be found in the wtmp artifact.

确定攻击者手动登录服务器并建立终端会话以执行其目标的 UTC 时间戳。登录时间与身份验证时间不同，可以在 wtmp 工件中找到。

Linux 用户登录信息放在三个文件中。

/var/log/wtmp 记录正在登录和历史登录系统的用户信息。

/var/log/utmp 记录当前正在登录系统的用户信息。

/var/log/btmp 记录失败的登录尝试信息。

这三个都是二进制文件，结构相同。

可使用 utmpdump <filename> 读取（新版 Debian/Kali 不再打包这个二进制）。

这里使用本题配套的 utmp.py 分析文件。

1

python3 utmp.py wtmp

找到了登录成功的这一行，但是发现时间对不上。

这是因为题目的 auth.log 用的是 UTC 时区，但是执行 python 脚本会用我们自己机器的时区。

使用 date 查看时区。

1

3

Mon Nov  9 11:08:53 PM EST 2026

当前时区是 EST，为 UTC-5 时区，所以比 UTC 慢五小时。

使用 timedatectl set-timezone 切换时区。

Task 5

The attacker added a new user as part of their persistence strategy on the server and gave this new user account higher privileges. What is the name of this account?

攻击者在其服务器上添加了一个新用户，作为其持久化策略的一部分，并赋予该新用户帐户更高的权限。该帐户的名称是什么？

攻击者先创建了 cyberjunkie 组，然后添加了新用户 cyberjunkie。

最后将 cyberjunkie 添加到 sudo 组，赋予了更高的权限。

答案：cyberjunkie

Task 6

What is the MITRE ATT&CK sub-technique ID used for persistence by creating a new account?

创建新帐户时，用于持久化的 MITRE ATT&CK 子技术 ID 是什么？

MITRE ATT&CK 是一套全球通用的、攻击者行为分类知识库 / 框架，把黑客攻击的步骤标准化命名、编号，方便取证、红蓝对抗、SOC、报告写作。全称 Adversarial Tactics, Techniques & Common Knowledge 对手战术、技术与常识。

一个十几个大战术 Tactic（TA00xx），每个里面又有技术 Technique（TAxxxx），技术中又有子技术（TAxxxx.00x）。详细可见 https://attack.mitre.org/matrices/enterprise/#。

持久化 Persistence 是 TA0003，这里用到的技术是创建账号 Create Account T1136，子技术是创建本地账户。

答案：T1136.001
